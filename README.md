# Дурка

Веб-приложение для Netlify: кидаешь скрины переписки, нейросеть читает их и выдаёт шуточное заключение врачебной комиссии. У каждого участника свой «индекс долбоебизма» (0-100), пародийный диагноз, цитаты-улики и отделение, от «здоров» до «буйного».

По умолчанию смотрит `openai/gpt-6-luna` через OpenRouter с `reasoning.effort: "max"`. Если он упал или не ответил, по цепочке зовутся запасные модели: другая модель OpenRouter, Groq, Gemini или любой OpenAI-совместимый сервер.

## Как устроено

```
браузер ──POST /api/submit──► submit (сохраняет скрины в Netlify Blobs)
   │                              └─► analyze-background (до 15 минут, ходит в LLM по цепочке)
   └──GET /api/result?id=… (раз в 2-4 с) ◄── результат в Blobs
```

- Синхронная функция Netlify по умолчанию живёт 30 секунд, а GPT-6 Luna на max effort может думать дольше. Поэтому анализ идёт в фоновой функции (лимит 15 минут), а страница опрашивает статус. Обновление страницы осмотр не прерывает.
- Длинные скрины переписки режутся в браузере на куски с нахлёстом, иначе модель ужмёт картинку и не прочитает мелкий текст. Всё сжимается в JPEG, чтобы влезть в лимит тела запроса (около 6 МБ).
- Скрины удаляются из хранилища, как только врач взял задание в работу. Результаты (и задания, которые так и не стартовали) чистятся раз в сутки функцией `cleanup`.

## Где лежит ключ и почему он не торчит наружу

Ключ никогда не попадает в браузер. Его читают только серверные функции.

1. **Переменная окружения Netlify** (основной способ). Функция читает `OPENROUTER_API_KEY` через `Netlify.env`, в статику и в сборку он не попадает.
2. **Админка `/admin`** (запасной способ, чтобы сменить ключ без редеплоя). Вход по паролю из переменной `ADMIN_PASSWORD`. Ключ сохраняется в Netlify Blobs на сервере. Обратно админка отдаёт только маску вида `sk-or-…1234`. Ключ из админки перекрывает переменную окружения, кнопка «Удалить из админки» возвращает переменную.

Дополнительно:

- Адреса OpenRouter, Groq и Gemini зашиты в код. Даже если кто-то подберёт пароль админки, отправить ключ OpenRouter на свой сервер он не сможет. Для «своего» провайдера адрес задаётся в админке, и при его смене сохранённый ключ стирается.
- Ошибки провайдеров вычищаются от ключей перед показом и логированием.
- `/api/submit` ограничен 8 запросами в минуту с одного IP, `/api/admin` 30 запросами (защита от перебора пароля). Это встроенный rate limiting Netlify, он работает на всех тарифах.
- Дневной лимит анализов (по умолчанию 200) и необязательный код доступа, чтобы случайные люди не жгли твои деньги.
- Строгий CSP, никаких сторонних скриптов, весь текст от модели выводится через `textContent`.

## Деплой на Netlify

1. Netlify → **Add new project → Import an existing project → GitHub** → этот репозиторий. Настройки сборки подтянутся из `netlify.toml`, трогать ничего не надо.
2. **Project configuration → Environment variables**, добавить:

   | Переменная | Обязательна | Что это |
   |---|---|---|
   | `OPENROUTER_API_KEY` | да* | ключ с [openrouter.ai/keys](https://openrouter.ai/keys) |
   | `ADMIN_PASSWORD` | для админки | пароль от `/admin`, минимум 10 символов |
   | `APP_PASSWORD` | нет | код доступа для пользователей, если не хочешь пускать всех подряд |
   | `GROQ_API_KEY` | нет | запасной провайдер |
   | `GEMINI_API_KEY` | нет | запасной провайдер |

   \* Можно не задавать и ввести ключ в админке.

   Если тариф позволяет, отметь ключи как **Contains secret values** и ограничь scope до **Functions**.
3. **Deploys → Trigger deploy**. Переменные окружения подхватываются только новым деплоем.
4. Зайди на `https://<твой-сайт>/admin`, введи пароль и нажми «Тест» у каждого врача в цепочке.

Совет по деньгам: на OpenRouter у ключа можно выставить лимит расходов. Поставь, это надёжнее любой защиты на стороне сайта.

## Цепочка моделей

Настраивается в админке: порядок, провайдер, id модели, reasoning effort, вкл/выкл. Провайдеры без ключа пропускаются.

| # | Провайдер | Модель | Effort |
|---|---|---|---|
| 1 | OpenRouter | `openai/gpt-6-luna` | `max` |
| 2 | OpenRouter | `openai/gpt-5.6-luna` | `high` |
| 3 | Groq | `qwen/qwen3.8-27b` | не передаётся |
| 4 | Gemini | `gemini-3.8-flash` | не передаётся |

Модели 3 и 4 взяты из документации провайдеров на сентябрь 2026 и провайдеры их регулярно переименовывают. Прежде чем на них полагаться, проверь кнопкой «Тест». Модель в цепочке обязана принимать картинки. Groq берёт максимум 3 картинки за запрос, поэтому на нём длинная пачка скринов может не пройти, тогда цепочка пойдёт дальше.

Effort для OpenRouter уходит как `reasoning: { effort, exclude: true }`, для остальных как `reasoning_effort`. GPT-6 принимает `none`, `low`…`max` и отклоняет `minimal`.

## Локальный запуск

```bash
npm install
npm i -g netlify-cli
echo 'ADMIN_PASSWORD=любой-пароль-подлиннее' > .env
echo 'OPENROUTER_API_KEY=sk-or-...' >> .env
netlify dev
```

Откроется `http://localhost:8888`. Blobs и фоновые функции эмулируются локально. Проверка типов: `npm run typecheck`.

## Ограничения

- Если на сайте включена парольная защита Netlify (Site protection), внутренний вызов фоновой функции тоже упрётся в неё. Для закрытия сайта используй `APP_PASSWORD`.
- Счётчик дневного лимита сбрасывается по UTC.
- Скрины уходят стороннему LLM-провайдеру. Предупреждение об этом есть в подвале страницы.
